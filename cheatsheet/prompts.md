# 부록 E 치트시트: 클로드에게 시킬 말

## 상황별 클로드에게 시킬 말

대표 문장만 골랐어요. 장 번호의 원문에는 앞뒤 설명과 확인 방법이 있습니다. 꺾쇠나 대괄호 부분은 내 것으로 바꾸세요.

### 막혔을 때

> 클로드에게: 아래 오류가 났어. 원인을 쉬운 말로 설명하고, 내가 터미널에 칠 명령을 한 줄씩 알려 줘. (오류 문장을 그대로 붙여 넣기)

(2장, 0장)

> 클로드에게: 방금 하려던 명령이 정확히 뭘 하는지 초보자도 알게 설명해 줘. 파일이 지워지거나 밖으로 나가는 게 있으면 알려 줘.

(2장)

### 저장하고 되돌리기

> 클로드에게: 지금까지 만든 걸 커밋해 줘. 커밋 메시지는 한국어로 "feat: 오늘 뭐 먹지 첫 화면 추가"로 해 줘. 커밋 전에 어떤 파일이 들어가는지 먼저 보여 줘.

(3장)

> 클로드에게: 방금 한 커밋을 취소해 줘. reset --hard는 쓰지 말고 git revert로 해 줘. 하기 전에 어떤 커밋을 취소하는지 보여 줘.

(3장)

### 규칙 가르치기

> 클로드에게: 방금 내가 고쳐 준 것을 CLAUDE.md에 한 줄 규칙으로 추가해 줘. 내용은 짧고 구체적으로 써 줘.

(4장)

> 클로드에게: 지금 읽고 있는 CLAUDE.md 파일들을 전부 알려 주고, 서로 모순되거나 너무 모호한 규칙이 있으면 찾아 줘.

(4장)

### 안전하게 시키기

> 클로드에게: 커밋 전에 비밀 키처럼 보이는 문자열이 있으면 커밋을 막는 pre-commit 검사를 이 저장소에 만들어 줘. 검사에 걸리는 가짜 키로 테스트도 해 줘. 진짜 키는 절대 쓰지 마.

(3장)

> 클로드에게: 이 스킬 폴더의 SKILL.md와 scripts 안 파일을 전부 읽고, 외부로 데이터를 보내거나 파일을 지우거나 키를 읽는 동작이 있는지 알려 줘. 설치는 내가 결정할게.

(6장)

### 사용량 아끼기

> 클로드에게: 지금까지 한 일을 5줄로 요약해서 NOTES.md에 적어 줘. 그다음 내가 /clear 하면 이 파일을 읽고 이어서 하게 할 거야.

(10장)

> 클로드에게: 지금 내가 쓰는 모델과 effort 설정을 알려 줘. 평소 코딩은 Sonnet으로 쓰고 싶은데 설정 파일에는 어떻게 적어야 하는지 공식 문서 기준으로 알려 줘.

(9장)

### 배포와 데이터

> 클로드에게: 아래는 Vercel 빌드 실패 로그야. 원인을 한 줄로 말하고, 고칠 파일과 줄을 알려 줘. 빌드 설정이나 환경변수를 바꿔야 한다면 먼저 이유를 말해 줘. 오류를 숨기려고 코드를 지우거나 검사를 끄지는 마. [로그 붙여 넣기]

(25장)

> 클로드에게: Supabase 오류를 분석해 줘. RLS를 끄거나 비밀 키로 바꾸는 해결책은 제안하지 마. 정책과 로그인 상태를 먼저 점검하고, 고칠 SQL이 필요하면 파일로만 써 줘. [오류와 정책 SQL 붙여 넣기. 키와 비밀번호는 지우고 붙이기]

(27장)

### 테스트

> 클로드에게: 아래 테스트 실패 로그를 읽고 원인을 두 가지 중 하나로 분류해 줘. (가) 앱이 잘못됨 (나) 테스트가 낡음. 코드는 아직 고치지 말고, 분류한 이유와 고칠 파일만 말해 줘. [여기에 로그 붙여 넣기]

(21장)

### 여러 개, 오래 맡기기

> 클로드에게: 서브에이전트 세 개를 동시에 돌려서 각각 알려 줘. 하나는 동네 선택 화면의 접근성 문제 3가지, 하나는 CSV를 JSON으로 바꾸는 코드의 빠진 예외 처리, 하나는 README에서 실행법이 틀린 곳. 서로 결과를 기다리지 말고 끝나면 한 표로 합쳐 줘.

(49장)

> 클로드에게: 지금 걸린 반복이 하루에 대략 몇 번 돌고 한 번에 토큰을 얼마나 쓰는지 `/usage` 기준으로 알려 줘. 줄일 방법도 두 가지 제안해 줘.

(53장)

> 클로드에게: 방금 목표가 20턴 만에 멈췄어. 어떤 실패가 반복됐는지 표로 정리하고, 다음 목표를 어떻게 쓰면 좋을지 한 문장으로 제안해 줘.

(52장)
