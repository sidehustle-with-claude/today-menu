# 부록 C 오픈소스 도구 지도

요금제: Pro로 충분

[그림 C-1: 책의 부별로 묶은 오픈소스 도구 지도]

이 부록은 언제 어떤 오픈소스를 쓰는지 찾아보는 길잡이입니다. 책에 나온 도구와 함께 자주 거론되는 오픈소스를 표로 모았습니다. 소개와 설치법은 쓰지 않습니다. 이름, 하는 일, 관련 장, 라이선스, 별 수만 비교합니다.

오픈소스는 만든 사람이 설계도인 소스 코드를 공개해서 누구나 가져다 쓰게 한 프로그램입니다. 라이선스는 그 프로그램을 어디까지 써도 되는지 적은 사용 허락서예요. 별 수는 GitHub에서 사람들이 "좋아요"처럼 누른 표시 개수로, 얼마나 많이 알려졌는지 보는 눈금입니다. 별이 많다고 품질이 보장되지는 않아요.

라이선스 이름은 이렇게 읽으세요.
- MIT, Apache-2.0: 상업 이용까지 허용하는 느슨한 허락서입니다. 저작권 표시만 남기면 됩니다.
- LGPL, GPL: 더 엄격한 허락서입니다. 이걸 넣어 만든 프로그램을 나눠 줄 때 소스 공개 같은 조건이 붙을 수 있어요.
- CC BY-NC-ND: 출처를 밝혀야 하고(BY), 돈 버는 데 쓸 수 없고(NC), 고쳐서 퍼뜨릴 수 없다(ND)는 조건입니다.
- 이름이 따로 붙은 라이선스(Remotion License 등): 조건이 제각각이라 원문을 직접 읽어야 합니다.

읽기 전에
- 별 수와 라이선스는 2026년 11월 1일에 공식 저장소에서 조회한 값입니다.
- 별 수는 매일 바뀝니다. 유지 중인지도 출간 직전에 다시 봅니다.
- 설치법은 각 저장소 README가 항상 최신입니다. 책에 옮기지 않습니다.
- 최신 표는 체크리스트 저장소(부록 A)에서 고칩니다. 저장소 주소는 책 앞부분 'A1 이 책 읽는 법'의 '책 저장소' 줄에 있습니다.
- 라이선스 칸이 "없음"이거나 조건이 길게 적힌 도구는 쓰기 전에 원문을 읽으세요.

[그림 C-2: 도구를 깔기 전에 공식 기능으로 되는지 먼저 보는 순서]

도구를 고르는 순서
- 1번: 클로드 코드의 공식 기능(스킬, 훅, 서브에이전트, `/loop`, `/goal`)으로 되는지 봅니다.
- 2번: 안 되면 오픈소스를 찾습니다. 라이선스와 최근 업데이트를 봅니다.
- 3번: 작은 작업에 하네스(어기지 못하게 묶는 틀, 51장)나 루프(반복, 53장)를 얹지 않습니다. 토큰만 늘어요.
- 4번: 설치 전에 코드를 읽을 수 있는지, 어떤 권한을 요구하는지 봅니다.

## 공식 기능으로 대신되는 부분

| 하고 싶은 일 | 먼저 볼 공식 기능 | 오픈소스를 쓸 때 |
|---|---|---|
| 반복되는 작업 절차 저장 | 스킬 | 남이 만든 절차를 가져다 쓸 때 |
| 특정 역할 분리 | 서브에이전트 | 역할 묶음을 통째로 쓸 때 |
| 도구 호출 전후 검사 | 훅 | 검사 규칙 묶음을 쓸 때 |
| 일정 간격 반복 | `/loop` | 단계가 많고 기록이 필요할 때 |
| 끝까지 맡기기 | `/goal` | 중간 점검을 단계별로 강제할 때 |

이름은 2026년 11월 기준 클로드 코드 공식 문서(https://code.claude.com/docs/en/commands)의 명령 목록과 맞췄습니다.

## 쓰지 말아야 할 때

- 하루에 끝나는 작은 작업에는 하네스나 루프를 얹지 않습니다.
- 공식 기능으로 되는 일은 오픈소스를 깔지 않습니다.
- 라이선스가 없는 저장소는 코드를 가져다 쓰지 않습니다.
- 최근 업데이트가 오래 멈춘 도구는 피합니다.
- 상업 서비스에 넣을 도구는 라이선스 조건(상업 이용, 재배포)을 먼저 읽습니다.
- 도구가 요구하는 권한이 하는 일보다 크면 쓰지 않습니다.

> 클로드에게: 이 표에서 내 목적에 맞는 도구를 골라 줘. 먼저 공식 기능으로 되는지 판단하고, 안 될 때만 후보를 말해 줘. 후보마다 저장소 README를 읽고 라이선스, 마지막 업데이트 날짜, 요구하는 권한을 확인해서 알려 줘. 확인 못 한 값은 `[확인 필요]`로 남겨 줘.
