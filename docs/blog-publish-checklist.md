# 블로그 공개 전 점검표 (29장)

블로그 저장소는 공개입니다. 올라간 글은 검색 엔진과 AI에게 읽히고, 지워도 사본이 남을 수 있습니다.

## 자동 점검

```bash
python3 scripts/check-blog-post.py blog-example/_posts
```

- 비밀 값(API 키, 토큰, 비밀번호), 이메일·전화번호·내 컴퓨터 경로를 찾으면 오류로 알립니다.
- 파일 이름 규칙, 머리말(title, date), 소제목, 이미지 대체 텍스트, 링크 글자를 확인합니다.
- 찾은 값은 출력하지 않고 파일 이름과 줄 번호만 보여 줍니다.
- 이 점검은 빠뜨릴 수 있습니다. 마지막 확인은 사람이 합니다.

## 넣으면 안 되는 것

| 넣으면 안 되는 것 | 이유 |
|---|---|
| API 키, 토큰, 비밀번호 | 올라가는 순간 유출로 봅니다 |
| 개인정보 (이름, 전화번호, 주소, 이메일, 계정 이름) | 되돌릴 수 없습니다 |
| 일하는 곳의 내부 이야기, 회사 코드 | 보안·계약 문제가 됩니다 |
| 남의 글·그림·코드 | 저작권 침해가 됩니다 |
| 클로드 대화 기록 통째 붙여넣기 | 위 항목이 섞여 있기 쉽습니다 |

## 사람이 읽을 때 보는 것

- [ ] 내가 겪지 않은 일이 섞이지 않았다
- [ ] 숫자와 이름이 맞다
- [ ] 내 말투가 맞다
- [ ] 회사 이름이나 업무 내용으로 읽히는 문장이 없다
- [ ] 출처 없는 긴 인용이나 복사한 코드가 없다

## 구조

- [ ] 글 파일 이름에 한글·공백이 없다 (`YYYY-MM-DD-영문-하이픈.md`)
- [ ] 제목은 머리말 `title` 하나
- [ ] 첫 문단이 이 글에서 무엇을 얻는지 2~3문장으로 알려 준다
- [ ] 소제목이 단락 내용을 짐작하게 한다
- [ ] 이미지 파일 이름이 내용을 알려 주고 대체 텍스트가 있다
- [ ] 링크 글자가 "여기"가 아니라 어디로 가는지 알려 준다

## 저장소

- [ ] 저장소 이름이 `<계정>.github.io` 이고 공개(public)다
- [ ] Settings → Pages → Source가 'Deploy from a branch', 브랜치 `main`, 폴더 `/ (root)`다
- [ ] 저장소에 `.env`, 메모, 초안 파일이 없다
- [ ] 푸시 후 10분 안에 주소가 열린다 (한 시간이 지나도 안 열리면 Actions 탭의 빌드 오류를 본다)
