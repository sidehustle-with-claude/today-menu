# 웹 콘솔 작업 안전 규칙 (43장)

콘솔은 내 계정의 내 항목만 다룬다. 남의 계정이나 남의 데이터를 대량으로 가져오는 일은 하지 않는다.

## 먼저

- 맡기려는 사이트의 이용약관에서 자동화나 로봇 접근 항목을 찾는다.
- 허용, 금지, 불분명 중 하나로 적어 둔다. 불분명하면 공식 API 가 있는지 찾는다.
- 보안문자를 푸는 일은 시키지 않는다.

## 방식 세 가지

- 클로드 코드의 크롬 연동 (`claude --chrome`): 화면을 보며 하는 방식. 토큰을 쓴다.
- 내 크롬을 AppleScript 로 조작하는 스크립트: 토큰 0. 화면 구조가 바뀌면 어긋난다.
- chromectl 같은 개인 도구는 이 저장소에 넣지 않았다. 같은 원리를 `scripts/console_fill.sh` 로 보여 준다.

## console_fill.sh

```bash
bash scripts/console_fill.sh store/intro.txt store/shots              # 읽기만 (기본)
DRY_RUN=0 bash scripts/console_fill.sh store/intro.txt store/shots    # 실제로 채움
```

- 가장 먼저 현재 탭 주소가 `config/allowed-domains.txt` 에 있는지 본다. 없으면 아무것도 하지 않는다.
- 로그인 화면이면 "로그인은 사람이 해 주세요" 하고 멈춘다.
- 칸을 못 찾으면 어떤 칸이 없는지 출력하고 에러로 끝난다.
- 소개 글은 `store/intro.txt`, 스크린샷은 `store/shots/` 에서 읽는다. 스크립트에는 값이 없다.
- 제출, 저장 후 심사 요청, 삭제, 결제 버튼을 누르는 코드는 없다.
- 시험: `bash tests/scripts/console-fill.test.sh` (가짜 osascript 로 흐름만 확인한다)

## 사람 몫

- 크롬 메뉴 '보기 > 개발자 > Apple 이벤트에서 JavaScript 허용'을 직접 켠다.
- 로그인, 문자 인증번호, 본인인증, 보안문자, 결제 인증.
- 마지막 제출 버튼.

## 울타리

- 허용 도메인 목록을 스크립트 맨 앞에서 검사한다.
- 삭제, 결제, 환불, 탈퇴는 코드에 넣지 않고 `CLAUDE.md` 에도 적는다.
- 제출 직전에 화면을 캡처해 폰으로 보내고(40장), 확인한 뒤에 사람이 제출한다.
- 비밀번호나 키를 스크립트에 쓰지 않는다. 로그인된 크롬 세션만 쓴다.
- 속도는 사람처럼 둔다. 한 번에 수백 번 요청하지 않는다.
