# 서브에이전트 (49장)

서브에이전트는 메인 클로드가 일을 맡기는 도우미 클로드다. 도우미마다 대화 기록(메모장)이 따로 있다.
공식 문서: https://code.claude.com/docs/en/sub-agents

## 이 저장소의 도우미

- `.claude/agents/code-finder.md`: 코드가 어디 있는지 찾는다. 읽기 도구만(Read, Glob, Grep), 모델 haiku.
- `.claude/agents/diff-reviewer.md`: 변경분을 검토한다. 읽기 도구만, 모델 sonnet. 파일을 고칠 수 없다.

```text
code-finder 에이전트로 즐겨찾기 저장 코드가 어디 있는지 찾아 줘.
diff-reviewer로 변경분 검토해 줘. 이번 변경은 즐겨찾기 버튼 추가다. [git diff 결과]
```

- 새 `agents` 폴더의 첫 파일이면 클로드 코드를 다시 시작해야 목록에 보일 수 있다.
- `tools` 에 Bash 만 적으면 읽기 전용이 아니다. 파일을 고치는 명령도 돌릴 수 있다.
- 공식 문서는 모르는 항목을 오류 없이 무시한다. 철자를 틀려도 조용히 넘어가니 실행해서 확인한다.
- 자동으로 안 불리면 `description` 을 "~할 때 쓴다" 형태의 구체적 상황 문장으로 고친다. 급하면 `@"code-finder (agent)"` 로 직접 부른다.

## 중첩 깊이

- `.claude/settings.json` 의 `env` 에 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` 을 넣었다. 도우미가 또 도우미를 부르지 않는다.
- 특정 도우미만 막으려면 그 파일의 `tools` 에서 `Agent` 를 뺀다.

## 병렬 실습 프롬프트

서로 결과를 기다리지 않는 일만 병렬로 돌릴 수 있다.

```text
서브에이전트 세 개를 동시에 돌려서 각각 알려 줘.
하나는 동네 선택 화면의 접근성 문제 3가지,
하나는 CSV를 JSON으로 바꾸는 코드의 빠진 예외 처리,
하나는 README에서 실행법이 틀린 곳.
서로 결과를 기다리지 말고 끝나면 한 표로 합쳐 줘.
```

같은 세 가지를 한 번은 순서대로, 한 번은 병렬로 시키고 휴대폰 타이머로 잰다. 사용량은 `/usage` 에서 본다.
표의 칸은 내 환경에서 직접 채운다. 이 저장소는 숫자를 대신 약속하지 않는다.

| 방식 | 걸린 시간 | `/usage` 의 사용량 |
| --- | --- | --- |
| 순서대로 | | |
| 병렬 | | |

## 쓸 때와 안 쓸 때

- 쓴다: 많이 읽고 요약만 필요한 탐색, 출력이 긴 일, 서로 독립된 일, 변경분 리뷰.
- 안 쓴다: 한 파일의 몇 줄을 고치는 작은 일, 순서가 있는 일, 내 대화 맥락이 꼭 필요한 일.
- 판단 기준: 이 일의 중간 과정을 나는 안 봐도 되는가.

## 비용

- 도우미마다 자기 요청을 따로 보내고, 사용량은 내 플랜에서 나간다. 메인 대화가 짧아지는 것과 전체 사용량이 줄어드는 것은 별개다.
- 줄이는 법: 탐색에는 `model: haiku`, 일을 좁게 시키기, 꼭 필요한 곳에만 쓰기.
- 한 세션에서 동시에 도는 도우미는 기본 20개까지다.

## 사람 몫

- 도우미에게 어떤 도구(특히 Bash 와 파일 수정)를 줄지 정하는 일.
- 도우미가 낸 리뷰를 따를지 판단하는 일.
