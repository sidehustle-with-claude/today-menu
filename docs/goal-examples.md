# /goal 목표 문장 모음

52장에서 쓰는 목표 문장입니다. 마음에 드는 문장은 복사해 두고 다음 목표에 재사용하세요.
평가 모델은 파일을 열지 않고 대화에 나온 것만 봅니다. 그래서 "클로드의 출력으로 증명할 수 있는 것"만 조건으로 씁니다.

## 좋은 목표와 나쁜 목표

| 나쁜 예 | 좋은 예 |
| --- | --- |
| 코드를 더 좋게 | `npm test`가 종료 코드 0이고 린트 경고가 0개 |
| 테스트 좀 고쳐 | `npm test` 12개가 모두 통과하고 테스트 파일은 수정하지 않음 |
| 느린 것 빠르게 | 추천 3개 함수가 CSV 1만 줄에서 1초 안에 끝남을 출력으로 보임 |
| 다국어 마무리 | `ko.json`과 `en.json`의 키 개수가 같다고 스크립트 출력으로 보임 |

## 실습 1: 실패한 테스트를 목표로 건다

한 문장으로 입력합니다. 줄바꿈은 읽기 쉽게 한 것입니다.

```text
/goal `npm test` 종료 코드 0, 실패 0개. 테스트 파일은 수정하지 않는다.
20턴 안에 못 끝내면 멈추고 이유를 보고한다.
```

## 실습 2: 무한 반복을 막는다

```text
/goal `npm test` 종료 코드 0. 아래 중 하나면 멈추고 보고한다.
20턴 경과 / 같은 실패 3번 연속 / 테스트·설정 파일을 고쳐야 통과.
```

- 턴 상한: 20턴. 넘으면 비용이 눈에 띄게 늘어납니다.
- 막히면 보고: 같은 실패 3번이면 멈춥니다.
- 제약: 테스트 파일은 수정하지 않습니다. 통과시키려고 테스트를 지우거나 느슨하게 바꾸는 편법을 막습니다.

## 조건에 넣는 세 가지

1. 측정 가능한 하나의 끝 상태(테스트 결과, 빌드 종료 코드, 파일 개수, 빈 대기열)
2. 확인 방법(`npm test`가 종료 코드 0, `git status`가 깨끗함)
3. 지킬 제약(다른 테스트 파일은 수정하지 않음)

조건은 최대 4,000자까지 쓸 수 있습니다.

## 목표에 넣지 않는 일

목표는 사람이 곁에 없어도 가는 기능입니다. 아래 일은 목표 문장에 "하지 않는다"로 적고, 끝난 뒤 사람이 따로 시킵니다.

- 운영 서버 배포
- 결제 연결, 실제 돈이 나가는 호출
- 데이터 삭제, `git push --force`
- 로그인과 본인인증

```text
/goal `npm test` 종료 코드 0. 배포, 결제, 데이터 삭제, force push는 하지 않는다.
20턴 경과 / 같은 실패 3번 연속이면 멈추고 보고한다.
```

## 상태 보기와 해제

| 하고 싶은 일 | 입력 |
| --- | --- |
| 목표 걸기 | `/goal 조건` |
| 상태 보기 | `/goal` |
| 해제 | `/goal clear` (별칭: `stop`, `off`, `reset`, `none`, `cancel`) |
| 새 대화 시작 | `/clear`도 목표를 지움 |

## 자리를 비우기 전: 권한

목표는 권한 모드를 바꾸지 않습니다. 이 저장소의 `.claude/settings.json`에는 목표가 도는 동안 물어보고 멈추지 않도록 아래 세 명령이 허용 목록에 들어 있습니다.

- `Bash(npm test)`
- `Bash(git diff *)`
- `Bash(git status)`

더 넓게 풀고 싶으면 자동 모드(`claude --permission-mode auto`)를 쓸 수 있습니다. 위 "목표에 넣지 않는 일"이 범위에 없는지 먼저 다시 읽으세요.
