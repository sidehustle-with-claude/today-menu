# 서치콘솔 등록 기록

35장에서 사람이 해야 하는 일과 저장소가 돕는 일을 나눠 적습니다. 로그인, 2단계 인증, DNS 편집 화면 로그인은 본인이 직접 합니다.
이 저장소는 서치콘솔에 로그인하거나 DNS 를 바꾸지 않습니다. 아래 표의 칸은 직접 채웁니다.

## 순서

| 순서 | 할 일 | 누가 | 도움 |
| --- | --- | --- | --- |
| 1 | 서치콘솔에서 도메인 속성 추가 | 본인 | |
| 2 | 알려 준 TXT 레코드(`google-site-verification=...`)를 DNS 에 추가. 호스트는 `@` 또는 비움 | 본인 | |
| 3 | 레코드가 들어갔는지 확인 | 본인 | `scripts/check-dns-txt.sh 내도메인` |
| 4 | 서치콘솔에서 확인 누르기. 실패하면 시간을 두고 다시 | 본인 | |
| 5 | 사이트맵 `sitemap.xml` 제출 | 본인 | `scripts/check-sitemap.sh https://내주소` |
| 6 | 소개 페이지에 URL 검사, 색인 생성 요청은 한 번만 | 본인 | |

확인에 성공한 뒤에도 DNS 레코드는 지우지 않습니다. 지우면 확인이 풀릴 수 있습니다.

## 소유권 확인을 메타 태그로 할 때

도메인 속성은 DNS 로만 확인됩니다. URL 접두어 속성을 쓰고 HTML 태그로 확인하는 경우에만, 서치콘솔이 준 값을 환경변수 `GOOGLE_SITE_VERIFICATION` 에 넣으면 `<head>` 에 태그가 들어갑니다(`src/verification.ts`). 값은 `.env.example` 에 넣지 않고 배포 환경에만 넣습니다.

## 색인 제외 사유를 만났을 때

- 사유 문구를 그대로 복사해 클로드에게 풀어 달라고 합니다.
- 코드와 `curl` 결과로 맞는지 확인한 뒤 고칩니다.
- 구글 공식 문서에 없는 해석은 "공식 확인 안 됨"이라고 표시합니다.
- 반영에는 며칠에서 몇 주가 걸립니다. 같은 주소에 색인 요청을 반복하지 않습니다.
