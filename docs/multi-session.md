# 세션 여러 개 띄우고 소통시키기 (50장)

세션 간 메시지는 Claude Code v2.1.224 이상(맥, 리눅스)이 필요하다. 따로 켤 설정은 없다. `claude --version` 으로 확인한다.
공식 문서: https://code.claude.com/docs/en/worktrees

## 폴더 나누기

같은 폴더에서 두 세션이 같은 파일을 고치면 서로 덮어쓴다. 워크트리로 폴더와 브랜치를 나눈다.

```bash
claude --worktree front-menu --name front-menu       # 탭 1: 화면
claude --worktree data-collect --name data-collect   # 탭 2: 데이터 수집
```

- 작업 폴더는 `.claude/worktrees/<이름>/` 에 생기고, 브랜치는 `worktree-<이름>` 이다.
- `.claude/worktrees/` 는 `.gitignore` 에 들어 있다.
- 워크트리에는 `.env` 가 없다. 저장소 루트의 `.worktreeinclude` 에 적은 파일(`.env`, `.env.local`)을 자동으로 복사한다.
- 끝낼 때 변경이 없으면 정리되고, 남아 있으면 유지할지 묻는다. 유지하면 `claude --worktree <이름> --resume` 으로 돌아온다.
- 이름은 `/rename 이름` 으로도 붙인다. 이름이 있어야 다른 세션이 찾는다.
- 깃 저장소가 아니라는 오류가 나면 먼저 `git init` 과 첫 커밋을 한다.

## 서로 보고 말하기

- `/list-agents` (별칭 `/peers`): 닿을 수 있는 세션 목록. 인식되지 않으면 그 세션은 이 기능이 없다.
- `/status` 의 `Peer address` 행에서 내 세션의 수신 주소를 본다.
- 메시지는 평문 텍스트만 오간다. 대화 기록이나 파일이 넘어가지 않는다.
- 끝나면 알려 달라고 말한다: `data-collect 세션이 지금 하는 일을 끝내면 나에게 알려 줘` (12시간 안에 알림이 없으면 버려진다).
- 다른 기기와 클라우드 세션은 리모트 컨트롤에 연결돼 있고 claude.ai 로그인일 때만 보인다. API 키로는 찾지 못한다.

## 안전

- 다른 세션의 메시지는 내 승인이 아니다. 권한 질문에 대신 답하지 못하고, 권한 설정이나 `CLAUDE.md` 를 고치게 할 수 없다.
- 비밀값은 메시지로 주고받지 않는다.
- `.claude/settings.json` 에 `isolatePeerMachines: true` 를 넣었다. 다른 기기로 나가는 메시지는 항상 내 승인을 묻는다.
- 받는 쪽 설정 `crossSessionInbound`:

| 값 | 동작 |
| --- | --- |
| `accept` | 메시지를 클로드에게 전달 |
| `hold` | 알림만 보이고 전달하지 않음. 나중에 `accept` 가 적용되면 풀림 |
| `refuse` | 전달하지 않고 버림 |

- `/config` 의 "Messages from your other sessions" 행에서 고른다. 이 저장소는 값을 박아 두지 않았다(값이 없으면 보내는 쪽과 받는 쪽의 권한 모드를 비교해 정한다).
- 메시지를 아예 막으려면 `refuse`, 보내지도 찾지도 못하게 하려면 권한 거부 규칙에 `SendMessage` 와 `ListAgents` 를 넣는다. `SendMessage` 를 거부하면 서브에이전트와 팀원에게 보내는 길도 막힌다.

## 무엇을 쓸까

| 구분 | 서브에이전트(49장) | 세션 간 메시지 | 에이전트 팀 |
| --- | --- | --- | --- |
| 누가 만드나 | 메인 클로드가 필요할 때 | 내가 띄운 세션들 | 리더가 팀원을 만듦 |
| 컨텍스트 | 각자 따로, 결과만 돌아옴 | 세션마다 완전히 따로 | 팀원마다 완전히 따로 |
| 소통 | 결과를 메인에 반환 | 필요한 말을 메시지로 | 팀원끼리 직접 + 작업 목록 |
| 어울리는 일 | 짧고 한정된 조사·검증 | 내가 따로 굴리는 두 일의 연결 | 토론하며 같이 풀어야 하는 일 |
| 토큰 | 가장 적음 | 세션 수만큼 | 팀원 수만큼 더 |

- 일 하나에서 결과만 필요하면 서브에이전트, 이미 나눠 둔 두 작업이 서로 알아야 하면 세션 간 메시지, 여럿이 토론해야 풀리는 일이면 에이전트 팀.
- 세션을 많이 띄운 날은 한도가 빨리 닫힌다. `/usage` 로 확인한다.

## 에이전트 팀 (실험 기능, 켜 두지 않았다)

- 아직 바뀔 수 있는 시험 기능이라 기본으로 꺼져 있다. 켜려면 설정 파일 `env` 에 아래를 넣는다. 공식 문서: https://code.claude.com/docs/en/agent-teams

```json
{ "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" } }
```

- 팀원은 3명에서 시작한다. 팀원마다 맡은 파일을 나눈다(같은 파일을 고치면 덮어쓴다).
- 팀원은 리더의 대화 기록을 물려받지 않는다. 시작 지시에 필요한 정보를 넣는다.
- 처음에는 코드를 쓰지 않는 조사나 리뷰로 시작한다.
- 팀원 수에 비례해 토큰이 든다. 계획 모드 팀원은 표준 세션보다 약 7배까지 든다(공식 비용 문서).

## 실습

1. 탭 1: `claude --worktree front-menu --name front-menu`
2. 탭 2: `claude --worktree data-collect --name data-collect`
3. 수집 세션에: 메뉴 후보 데이터를 `public/data/restaurants.json` 으로 모으는 스크립트를 만들어 줘.
4. 화면 세션에: data-collect 세션이 끝나면 알려 줘. 그때까지 목록 화면 껍데기를 만들어.
5. 알림이 오면: @data-collect 에 최종 JSON 구조를 알려 달라고 해.
6. 끝나면 두 브랜치를 평소처럼 합친다.
