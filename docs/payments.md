# 결제 (토스페이먼츠 테스트 / 가짜 결제창)

이 저장소의 결제는 연습용입니다. 실제 돈은 오가지 않고, 실서비스 키(`live_`)는 코드가 거부합니다.

## 결제 방식 고르기

- 웹 서비스의 카드·간편결제는 PG사 결제창(여기서는 토스페이먼츠 결제위젯)을 씁니다.
- 앱스토어에 올리는 앱의 디지털 상품은 스토어 인앱결제 규칙이 따로 있습니다. 39장에서 공식 문서로 다시 확인합니다 [공식 확인 안 됨].
- 사업자 등록, 통신판매업 신고, 환불 규정 등 법령 내용은 원문을 확인한 뒤 적습니다 [법령 원문 확인 못 함].

## 흐름

1. `POST /api/payments/order`: 서버가 상품과 금액을 정해 주문을 만듭니다. 화면이 보낸 금액은 믿지 않습니다.
2. 결제창에서 인증이 끝나면 `successUrl` 로 `paymentKey`, `orderId`, `amount` 가 돌아옵니다.
3. `POST /api/payments/confirm`: 서버가 저장해 둔 금액과 같은지 비교한 뒤에만 승인을 요청합니다. 다르면 `amount_mismatch` 로 남기고 승인하지 않습니다.
4. 같은 주문을 다시 확인해도 한 번만 처리합니다(멱등).
5. 창을 닫거나 거절되면 `failUrl` 로 와서 `POST /api/payments/fail` 이 상태를 남깁니다. 창을 닫으면(`PAY_PROCESS_CANCELED`) `orderId` 가 오지 않아서 브라우저에 적어 둔 값을 씁니다.
6. 웹훅(`POST /api/payments/webhook`)은 받은 내용을 믿지 않고 결제 조회로 다시 확인합니다. 같은 이벤트는 한 번만 처리하고, 확인하지 못하면 5xx 로 응답해 다시 받게 합니다.

## 모드

| 모드 | 조건 | 동작 |
| --- | --- | --- |
| test | `TOSS_SECRET_KEY` 가 `test_` 로 시작 | 토스페이먼츠 테스트 환경 호출 |
| mock | 키 없음 + (개발 환경 또는 `PAYMENTS_MOCK=1`) | 가짜 결제창, 외부 호출 없음 |
| off | 키 없음 + 운영 환경 | 결제 화면이 꺼져 있다고 표시, API 는 503 |
| 거부 | 키가 `live_` 로 시작 | 결제를 막고 오류 |

## 시험한 것과 못 한 것

## 한계

- 주문은 서버 메모리에 있어서 재시작하면 사라집니다. 실서비스에서는 DB 가 필요합니다.
- 프리미엄 상태는 화면에 표시만 하고, 즐겨찾기 개수 제한 같은 기능에는 연결하지 않았습니다.
